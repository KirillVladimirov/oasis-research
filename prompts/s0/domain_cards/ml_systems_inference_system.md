Domain: **ml_systems_inference_system**. This domain studies the **software–hardware serving stack** for deploying ML models (increasingly generative/LLM workloads) under production constraints—tight latency/SLOs, high throughput, multi-tenancy, and cost/energy limits. Core elements include request routing and admission control; **batching and scheduling** (including preemption and SLO-aware policies); memory-centric techniques (activation/KV-cache management, compression/pruning, CPU/NVMe offload, fragmentation handling); **prefill–decode coordination** for LLMs; speculative decoding and streaming; adapter/multi-model serving (e.g., many LoRA variants); autoscaling and disaggregated architectures that separate compute and decision/control planes. A typical loop instruments a target serving workload, identifies bottlenecks (GPU underutilization, KV-cache memory pressure, tail-latency spikes, burstiness), applies system interventions (scheduling/batching, cache policies, offload/compression, parallelism/placement, autoscaling), and re-evaluates under realistic traffic; evaluation emphasizes median and tail latency, throughput/tokens-per-second, GPU utilization, scaling efficiency, and cost-per-request (or cost-per-quality under quality-aware serving).
